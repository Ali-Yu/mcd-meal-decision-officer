# 麦麦饭点决策官

> 同一顿饭，换个时段，就是完全不同的决策。

基于 **麦当劳官方 MCP** 的智能点餐 Skill。

不替你「算最便宜」，而是帮你在真实饭点压力下，**快速做出可执行、可解释、可分享的最终决定**。

---

## 一、核心创新点

| 能力 | 说明 |
|---|---|
| **时段感知** | 先获取当前时间，判断饭点，再切换决策权重。同一套餐在工作午餐和加班宵夜会得到完全不同的结论。 |
| **多目标权衡** | 预算、热量、口味、忌口、新品、公平性一次打分，先过滤硬性约束。 |
| **固定输出** | 永远输出【麦麦饭点决策】+ A/B/C 三方案 +【决策卡片】，不可省略。 |
| **可解释** | 每套方案必须说清楚「为什么推荐、放弃了什么」。 |
| **真实数据** | 全部来自官方 MCP；缺少数据时标注「暂无可靠数据」，禁止编造。 |
| **优雅降级** | 无位置只问一句，无预算标注「未设置」，可降级为搭配草案。 |
| **交易安全** | 默认只提供方案；下单须复述明细并单独确认；变更内容后原确认作废。 |

## 二、30 秒看懂它解决什么问题

点麦当劳时最常见的纠结：

- 现在到底该吃轻一点还是吃饱一点？
- 预算紧的时候怎么搭配才不后悔？
- 三个人聚餐，有人控卡、有人不吃辣，怎么点才公平？
- 想尝新品又怕踩雷？

传统推荐只给一个「最优解」。

**麦麦饭点决策官**永远给你三套有明确取舍的方案，并附上可直接转发的决策卡片。

## 三、输出长什么样

以下为输出格式示例，商品、价格、优惠及热量均须以实际 MCP 查询结果为准。

```text
【麦麦饭点决策】时段：加班宵夜｜人数：1｜预算：≤40元

推荐方案：

A. 最省方案
- 组合：板烧鸡腿堡 + 中薯条
- 实付 ¥28.5（原价 ¥36，已用券）
- 热量 720 kcal
- 决策理由：宵夜时段优先低负担，放弃了套餐饮料以控制总热量。

B. 最均衡方案（推荐）
- 组合：麦辣鸡腿堡套餐（可乐换无糖）
- 实付 ¥32.0
- 热量 680 kcal
- 决策理由：兼顾饱腹与控卡，无糖可乐降低饮料的糖摄入。

C. 最开心方案
- 组合：新品鸡腿堡 + 麦旋风
- 实付 ¥39.5
- 热量 890 kcal
- 决策理由：满足「想吃点好的」的情绪，适合偶尔享受。

【决策卡片】（可直接转发）

时段目标：低负担不撑

最终建议：选 B，因为宵夜更看重整体饮食负担，而非极致省钱。

取舍说明：放弃了最便宜的组合，换来更符合当前需求的搭配。
```

## 四、快速开始

### 1. 获取麦当劳 MCP Token

前往 [麦当劳 MCP 官方平台](https://open.mcd.cn/mcp)，按照以下步骤操作：

1. 手机号登录。
2. 进入控制台。
3. 激活 MCP 服务。
4. 复制 Token。

### 2. 在 WorkBuddy 中配置

将仓库中的 `mcp-config.example.json` 配置内容粘贴到 WorkBuddy 自定义连接器。

将 `${MCD_MCP_TOKEN}` 替换为自己的真实 Token。

**安全提醒：** 真实 Token 仅用于本地配置，禁止提交到公开 GitHub 仓库。

### 3. 导入 Skill

将本仓库的 `skill/SKILL.md` 导入 WorkBuddy，即可开始对话。

### 4. 示例对话

- 「现在是晚上 9 点半，一个人，预算 40，不想撑，帮我决策。」
- 「三个人聚餐，人均 50，有一个不吃辣，一个控卡。」
- 「想优先尝新品，预算 45。」
